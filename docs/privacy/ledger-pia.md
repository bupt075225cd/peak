# 家庭资产账本 个人信息保护影响评估（PIA）

- 评估对象：Peak 多应用平台中的「家庭资产账本」（`/ledger`，服务 `apps/asset-service`）
- 告知版本：`ledger-consent-v1-2026-10`（与 `libs/domain.LedgerConsentPolicyVersion` 保持一致，升级版本号即需用户重新同意）
- 评估结论：在落实本文件所述措施的前提下，处理活动对个人权益的影响可控；残余风险已明示并接受。

## 1. 处理活动与合法性基础

| 项目 | 内容 |
| --- | --- |
| 处理目的 | 记录家庭资产与负债、按月生成快照、展示资产结构（桑基图）与月度回顾 |
| 处理的信息 | 资产/负债名称、金额、币种、资产类型、子类、备注、成员昵称（均为用户主动填写） |
| 信息类别 | 金融账户类**敏感个人信息**（《个人信息保护法》第 28 条） |
| 合法性基础 | 用户的**单独同意**（第 29 条）；同意前不进行任何读写，接口返回 403 |
| 最小化 | 不收集身份证号、银行卡号、手机号；服务端对名称/备注做直接标识符正则拦截 |
| 共享 | 不向任何第三方共享；不使用广告或分析 SDK；导出仅在用户主动触发时返回其本人数据 |

## 2. 数据流与安全措施

```
浏览器（金额不落 localStorage / URL）
  → 网关（JWT 校验、按用户限流、安全响应头、X-User-Id / X-Token-Iat 注入）
  → asset-service
      ├─ owner_ref = HMAC-SHA256(LEDGER_ID_KEY, "peak-ledger|" + user_id)
      ├─ DEK = HKDF-SHA256(KEK, 每用户随机盐, "peak-ledger-dek-v1")
      ├─ 密文 = AES-256-GCM(DEK, 明文, AAD = owner_ref|row_uid|字段名)
      └─ row_mac = HMAC-SHA256(MAC_KEY, 规范化字段 + 密文摘要 + version + updated_at)
```

1. **信封加密**：敏感字段（名称、金额、备注、子类、成员名、快照载荷）以 AES-256-GCM 密文落库，随机 12 字节 nonce，AAD 绑定主体、行标识与字段名，防止跨行/跨字段重放。
2. **去标识化**：业务表不含 `user_id`、手机号、邮箱、姓名，只有不可逆伪名 `owner_ref`。伪名密钥与主密钥、MAC 密钥三把分离，任一单独泄露都不足以还原数据或反查到人。
3. **完整性**：行级 HMAC 可检出数据库层静默篡改（命中即告警）；条目更新使用 `version` 乐观锁（冲突返回 409）；审计日志以 `prev_hash` 链式追加，无法无声改写或截断。
4. **密钥装载 fail-fast**：生产（`LEDGER_ALLOW_DEV_KEYS=false`）缺失密钥、长度非 32 字节或仍等于内置开发密钥时进程直接退出，避免带弱密钥上线。
5. **访问控制**：条目查询一律附带 `owner_ref` 条件，越权访问统一返回 404（不泄露资源存在性）；导出、注销需 5 分钟内签发的令牌（否则 428 要求重认证）；网关按用户令牌桶限流。
6. **传输与浏览器侧**：全站 HTTPS + HSTS；响应头含 `nosniff`、CSP、`Referrer-Policy`；金额不进 URL、不进 localStorage，页面切后台（`visibilitychange`）自动隐藏，日志与控制台不打印金额、名称与成员名。
7. **导出与删除**：全量导出为 JSON 文件流（含条目、成员、快照、同意留痕与审计摘要），下载图叠加会话伪名水印；注销申请后 30 天冷静期可撤销，到期销毁 `ledger_keyrings` 行实现**密码学删除**——密文仍在备份中也永久不可解。

## 3. 留存期限

| 数据 | 留存策略 |
| --- | --- |
| 条目、成员、快照 | 用户主动删除或注销冷静期结束时删除 |
| 密钥盐（keyring） | 随注销一并删除，删除后不可恢复 |
| 同意留痕 | 保留至注销完成（合规举证需要），不含金额与名称 |
| 审计日志 | 保留动作、目标类型/ID、哈希与时间，不含金额、名称；注销后仅保留 `purged` 事件 |
| 注销申请记录 | 冷静期结束并执行删除后归档状态（`completed`），不含业务数据 |

## 4. 残余风险与缓解

1. **准标识符明文**：`category`（5 类枚举）、`period`（月）、`updated_at`、`currency`、`risk_type` 为明文，用于索引与按月聚合。单独不足以识别个人，但与外部数据结合可能推断「某人有一笔房贷」。缓解：不存任何直接标识符，伪名跨库不可关联；该风险在告知中明示。
2. **服务端可见明文**：记账需要服务端聚合与多端一致，因此明文在请求处理期间存在于进程内存。缓解：不落盘、不写日志、不缓存，请求结束即释放；主机被完全控制属于极端场景，已在告知中说明。
3. **伪名可枚举性**：若攻击者同时掌握 `LEDGER_ID_KEY` 与候选 user_id 列表，可验证某用户是否使用账本。缓解：密钥仅存在于进程环境变量，与数据库分离；轮换 ID_KEY 会使历史伪名失效（需迁移）。
4. **浏览器侧泄露**：屏幕被旁人看到、截图外传。缓解：一键隐藏、切后台自动隐藏、下载图水印、金额不进可分享的 URL。
5. **令牌被盗**：攻击者持有效令牌可读账本。缓解：短 TTL、敏感操作要求新鲜令牌、按用户限流与审计留痕。

## 5. 用户权利实现方式

| 权利 | 实现 |
| --- | --- |
| 知情权 | 首次进入账本弹出《敏感个人信息处理告知》，版本号可查 |
| 同意与撤回 | 每次使用前单独勾选；不勾选则不进行任何读写；撤回方式为注销账本 |
| 查阅、复制 | 「导出全部数据」生成 JSON 文件（可携带权） |
| 更正 | 条目编辑（写审计）、成员重命名 |
| 删除 | 单条删除即时生效；整体注销 30 天冷静期后密码学删除 |
| 解释说明 | 本文档 + 页面隐私提示条 |

- [ ] `LEDGER_ALLOW_DEV_KEYS=false`，启动日志无开发密钥告警
